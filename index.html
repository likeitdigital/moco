Brand guidelines can become interfaces.

MOCO is a small experiment in living brand systems: shape, colour, expression and motion are not separate decisions but one design language. Instead of thirty finished files, you hand someone the studio they are made in.

The idea

A brand asset doesn't have to be finished when you export it.

Branding usually ends with a handover: logo, colours, type, a few illustrations, a PDF that explains the rules. Everything in that package is fixed. Every new variation means going back to the designer.

A static brand system

  • A fixed set of files
  • Rules written down as text
  • Motion added later, by someone else
  • Every variation is a new request
  • The guidelines describe the system

A living brand system

  • A studio with defined boundaries
  • Rules enforced by the interface
  • Motion is part of the identity
  • New variations are made on the spot
  • The guidelines are the system
What it does

Four decisions, one character.

Each property is independent. Changing the shape never resets the expression, adding motion never clears what you built — and what you export is exactly what you see on screen.

Shape & colour

Six organic silhouettes, a curated palette and any custom colour. The face colour is derived from the brand colour rather than set separately.

States, not moods

Idle, Hello, Thinking, Success, Oops, Attention — the moments a product actually needs: empty states, loading, confirmation, error.

Motion on a timeline

Eight motions, arranged by dragging. Every clip runs whole cycles, so a sequence loops without a jump — in the browser and in the exported file.

How it was made

Built as a design experiment — and tested like a product.

MOCO started from a question: what happens when designers don't just create the assets, but the tools that generate them? Rapid prototyping and AI-assisted development make it possible to design the rules and behaviour behind an output, not only the output itself — an interesting space between branding, product design and creative tooling.

The instructive part turned out to be the testing. The first version looked finished and behaved correctly on screen — and exported the wrong character every single time. The preview was right, the file was not. Two more faults were invisible in the interface too: the size control was silently overridden by every motion, and the exported animation jumped on each loop. None of that showed up by clicking around; it only showed up by opening what got downloaded, next to what was on screen.

That discipline — checking the file against the screen, not just the screen against itself — became a short German guide, Der Funktionsbeweis, using the real faults from building MOCO as its examples. The same rigour carried through later, when the phone layout was rebuilt from a scrolled-down desktop page into a fixed app screen: shape, colour and motion controls as sheets over the stage, a tab bar instead of a long list, nothing cut off, nothing hidden behind a panel that hasn't reported its own height yet.
